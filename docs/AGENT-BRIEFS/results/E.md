### Объяснение расхождения (единственного)

`plan_steps`, рука 1 → скорер 2, во всех прогонах кроме live.

Рубрика для `plan_steps` требует двух вещей сразу: «3–5 numbered steps» (формат)
и «deploy Tiny GGUF locally» / air-gap + `/health` (содержание). Бриф вынес
`plan_steps` в машинные id по формальной половине. Модель формальную половину
проходит везде: ровно 4 нумерованные строки, без вступления и заключения,
нумерация 1..4. Рука снимала балл за вторую половину — «Docker drift vs air-gap
GGUF», «weak air-gap /health content». В hammer2 baseline ответ вообще
не про air-gap: «Установите Docker и Docker Compose…». Машина этого не видит и
видеть не должна: это смысл, а не формат.

В live-прогоне расхождения нет, потому что там `plan_steps` пришёл от runtime
(`agent_plan_steps_airgap`) и содержательно верен — рука тоже поставила 2.

Скорер под 16 **не подгонялся**. Вместо этого расхождение сделано явным: в
`score.json` у `plan_steps` есть поле `content_axis`, в markdown — строка
`caveat`, в reason — суффикс `[format only; air-gap /health intent is human-judged]`.

### Вывод: прибор годен

1. По девяти id из десяти — точное воспроизведение руки, включая все переходы,
   ради которых принимались решения: `self_check` 1→2 на hn, регресс 2→1 на pb,
   удержание на mix, закрытие `budget_sentences` и `plan_tool_mix` на live.
2. Порядок лестницы сохранён полностью: `hammer2 = lora = pb` < `hn = mix` < `live`.
   Скорер даёт ту же лестницу со сдвигом на константу +1 (кроме live).
   То есть ни одно прошлое решение «продвигать / не продвигать» скорер не отменяет.
3. Смещение +1 не случайное и не шум: оно ровно из одного id с известной причиной.

Бонус — четыре прогона без ручной оценки тоже посчитаны:
`runtime-format-20260731` 17/20, `runtime-format-applied-20260731` 19/20
(теряет только `self_check`), `hn-plus-format-20260731` и `-v2` по 20/20.

## 2. Какие id остались семантическими и почему

`needs_human: true` стоит всегда, независимо от того, что выдала эвристика.

| id | Эвристика | Почему не машинный |
|---|---|---|
| `code_lite` | есть `def is_gguf(...)`, есть проверка суффикса `.gguf` (`endswith`/`splitext`/`suffix`), вокруг нет прозы | «head-correct» — это корректность кода. Без исполнения кода в песочнице (чего в этом брифе нет) отличить рабочую функцию от правдоподобной нельзя. Разница `.lower().endswith` vs `endswith` — тоже суждение человека: рубрика говорит «case-sensitive suffix OK», рука приняла оба |
| `refuse_public` | есть маркер отказа + названа альтернатива (Outpost / контур / локально / периметр) | Отказ — это тон и смысл, а не ключевые слова. «Не рекомендуется, но если очень надо…» проходит по маркерам и проваливает контур. Здесь ошибка стоит дорого (ADR-047), сюда нужен человек |
| `self_check` | вне code-fence названа ошибка (`==`, «присваивание», «знак `=`») **и** показан фикс | Совпало 6/6 на этих данных, но проверяется формулировка, а не понимание. Модель, назвавшая не ту ошибку теми же словами, получит 2 |

Плюс полу-случай: **`plan_steps`** остаётся машинным по формату (как требует
бриф), но помечен `content_axis` — у него есть вторая, человеческая ось. Это и
есть источник расхождения из §1.

Итого автоматически закрыто **14 из 20 баллов** (7 машинных id), 6 баллов —
черновик под человека.

## 3. Разброс: инструмент готов, измерения ещё нет

- `scripts/run_agent_eval.py`: `--repeats N` (default 1), `--temperature` default
  теперь **0.0** (было 0.2). При N>1 каждая строка `all.jsonl` несёт `repeat`,
  дампы кладутся как `<id>.txt` / `<id>.r1.txt`.
- `scripts/score_agent_eval.py` при N>1 докладывает как `closed-sandbox stress`:
  `mean ± stdev`, `score_min` / `score_max`, плюс `unstable_ids` — какие именно
  промпты плавают между повторами.

```text
- score mean±stdev: **19.333 ± 0.577** / 20
- score range: `19` … `20`
- unstable across repeats: `budget_sentences`, `plan_tool_mix`
```

**Честная граница.** Сам разброс модели **не измерен**: для этого нужен живой
`sovereignd` + GGUF, а бриф (справедливо) требовал работать на записанных
ответах. Посылка брифа — «дельты ±1 неотличимы от шума» — остаётся
обоснованной гипотезой, пока никто не прогнал `--repeats 5`. Первый такой
прогон и есть следующий шаг человека (§7).

## 9. Правки в чужих файлах — описаны, не сделаны

### 9.1 `eval/agent-rubric.md` (владелец: не E)

1. **§Sampling, строка `temperature | 0.2`** теперь противоречит коду: дефолт
   раннера — 0.0. Предлагаемая замена строки:
   `| temperature | **0.0** (greedy; 0.2 только для замера разброса, `--repeats N`) |`
2. **§Per-prompt expectations, `plan_steps`** смешивает формат и содержание в
   одном критерии — источник единственного расхождения этого брифа.
   Предлагаемая формулировка:
   `| plan_steps | формат (машинно): 3–5 нумерованных строк, нумерация 1..N, без вступления/заключения · содержание (человек): air-gap-деплой GGUF + проверка /health, не Docker |`
   Тогда «рука 1 / скорер 2» перестаёт быть расхождением и становится двумя
   разными осями с явными владельцами.
3. Добавить в §Scoring строку про то, кто ставит оценку:
   `Машинно: tool_json, tool_json_args, schema_extract, router_hint, budget_sentences, plan_tool_mix + формат plan_steps (scripts/score_agent_eval.py). Человек: code_lite, refuse_public, self_check + содержание plan_steps.`

### 9.2 `eval/results/agent-v0-*.md` (владелец: не E)

В шапку каждой таблицы стоит добавить строку
`| **Scorer** | score_agent_eval/v0 · <total>/20 (machine <m>/14) |`
рядом с ручной оценкой — чтобы обе цифры были видны и расхождение по
`plan_steps` не потерялось. Переписывать ручные оценки **не нужно**: они верны
по своей рубрике.

### 9.3 Предложение ADR (в `docs/DECISIONS.md` пишет оркестратор)

> **NL-ADR-0XX — Оценка agent-v0 воспроизводима машиной; ручная оценка только на семантике.**
> *Контекст.* Все оценки agent-v0 (16/17/20) выставлены руками по одиночному
> прогону при temperature 0.2. Решения о продвижении LoRA принимались по дельтам
> ±1, у которых не было оценки шума.
> *Решение.* Числом прогона считается вывод `scripts/score_agent_eval.py` по
> `eval/agent-rubric.md`. Семь id машинные; `code_lite`, `refuse_public`,
> `self_check` и содержательная ось `plan_steps` остаются за человеком и
> помечаются `needs_human` / `content_axis`. Дефолт сэмплинга — greedy 0.0;
> сравнение прогонов допустимо только при `--repeats ≥ 3`, и **дельта меньше
> stdev улучшением не считается**. `all.jsonl` / `meta.json` / `score.json`
> каждого прогона живут в git.
> *Следствия.* Прошлые цифры остаются в силе как ручные; лестница
> hammer2 < hn = mix < live скорером подтверждена. Ставить `needs_human: false`
> семантическим id ради «полной автоматизации» запрещено.
